# 验收清单

下面所有人工验收项初始均为未执行。执行者填写设备型号、系统、编辑器版本、时间和结果；不要把步骤当作结果。

## Unity 真机（必须完成）

- [ ] Unity 导入无编译错误，构建 APK 并安装在 ARCore 支持的真机上。
- [ ] 首次相机权限允许后有实时背景；拒绝权限时观察系统/AR 状态，不声称检测成功。
- [ ] 扫描水平面出现绿色平面，AR 状态 SessionTracking。
- [ ] 点击平面放置球，点击新位置移动球；坐标与命中位置相符。
- [ ] 点击 URL、标题、描述、Priority、Submit 和表单空白区域都不会移动/放置球。
- [ ] 空标题、全空格标题、未放标记均不能提交，提示原因。
- [ ] low / medium / high 各上报一次，包含至少一次中文标题和一次空描述。
- [ ] 成功提示 ID，失败提示明确；断网或错误地址时内容不丢失，可修正后重试。
- [ ] 失去 AR 跟踪时不能继续提交，恢复后可操作。

## 三端闭环（必须使用手机实际上报）

1. 启动同一个 Go 后端，记下日志中数据文件绝对路径。
2. 手机 `/health` 可达，Unity 上报“入口墙面破损”，记录返回 ID。
3. React 刷新后找到相同 ID 对应问题，核对标题、描述、优先级和坐标。
4. 修改为 in_progress，再改 resolved；刷新页面后仍为 resolved。
5. 停止 Go，确认 React 刷新/状态更新出现错误而不是白屏。
6. 在原目录重启 Go，确认同一条 ID、原 createdAt、最新状态和坐标仍存在。
7. 后端停止时手机提交，确认失败提示且不清空表单。后端恢复后重试并检查无意外重复。

## 建议演示顺序（约 5 分钟）

手机扫平面 → 点击输入框证明不误放 → 放球填表 → 成功 ID → 电脑刷新 → 改状态 → 重启 Go → 确认数据保留 → 停 Go 展示网页错误提示。
